# Releases

- Every user-visible change adds a line under `## Unreleased` in `CHANGELOG.md` in the same commit
  (grouped as `### New`, `### Fixes`, `### Changes`). Write it for people running the panel: what
  they see or can do now, not file or function names. Dependency bumps get one summary line.
- To release vX.Y.Z: rename `## Unreleased` to `## vX.Y.Z - <YYYY-MM-DD>`, add a fresh empty
  `## Unreleased` above it, commit, then tag. The release workflow fails if the tag has no section.
- The GitHub release notes are generated by `tools/dist` (`writeNotes`): the tag's changelog section
  first, then the fixed install / upgrade / Docker block. Don't hand-write release notes and don't
  put the change list anywhere else. Preview with
  `go run ./tools/dist -version vX.Y.Z -notes-only && cat dist/NOTES.md`.
- The Docker image is only `ghcr.io/genguzzz/sbpanel:latest` and is not rebuilt per release; it
  downloads the newest release on start. Don't add version tags to it.
